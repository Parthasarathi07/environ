# data/ — the panel this project reads

Two files, both CSV, both regenerated by code:

| file | grain | produced by |
|---|---|---|
| `panel.csv` | one row per firm per month | `python -m environ.data.generate_data` (demo) or `python -m environ.data.build_real_panel` (real) |
| `firms.csv` | one row per firm | same |

**Everything in this repo — the app, the memo, the deck, the interview pack — is
derived from these two files. Nothing is hard-coded downstream.** Change the
panel, re-run, and even the English sentences in the verdict rewrite themselves.

## `panel.csv` — column contract

`stats.py` reads exactly these names. Required columns raise on absence;
optional ones degrade with a message in the app's Data tab rather than a crash.

| column | req | meaning |
|---|---|---|
| `date` | ✅ | month-end, `YYYY-MM-DD` |
| `ticker` | ✅ | firm id |
| `sector` | ✅ | GICS level-1 name — **the whole project turns on this** |
| `esg_score` | ✅ | published 0-100 rating for that month |
| `ret_m` | ✅ | total return, **percent per month** (0.85 = 0.85%) |
| `esg_momentum_z` | ✅ | z-score of the trailing 12-month rating change |
| `esg_z` | — | cross-sectional z of `esg_score`; derived if absent |
| `idio_vol_ann` | — | annualised firm-specific vol, % — needed for the risk table + risk regression |
| `realised_vol_ann` | — | 12m rolling realised vol |
| `beta` | — | market beta |
| `ev_bn` | — | enterprise value $bn — needed for the size control |
| `esg_persistent`, `esg_reported_change_12m` | — | demo-only: the underlying rating vs the published one, used for the measurement-error note |

`year` and `month` are derived from `date` if missing.

## Units — the most common way to break this

`ret_m` is **percent per month**, not a decimal. A regression coefficient of
`10.0` means 10 basis points per month per one standard deviation of the
driver. Feed the loader decimals and every number in the project shrinks by
100×, silently. `build_real_panel.py` multiplies by 100 for you.

## The demo panel is synthetic — and says so

`generate_data.py` builds it from named assumptions in `environ/config.py`
(ESG level → return, momentum → return, level → volatility), with a fixed seed
so it is reproducible. Sector compositions, the 2021 energy rally and the 2022
rate shock are calibrated to match how the published literature describes them,
but **no MSCI licence, no Bloomberg and no price feed was used** — the sandbox
this was built in blocks those hosts.

Use it to demo the method. Do not quote its magnitudes as facts.

## Swapping in real data

```bash
# 1. ratings: ESG-Book (CC-BY-4.0), quarterly, 4,000+ firms
#    https://huggingface.co/datasets/ESG-Book/esg  -> Files -> data.csv
# 2. prices: monthly adjusted closes
pip install yfinance
# 3. merge (tolerates column name variants; refuses to run without sector)
python -m environ.data.build_real_panel \
    --ratings esg.csv --prices prices.csv \
    --out environ/data/panel.csv
# 4. the app reads the new panel at boot
uvicorn environ.app:app --reload
```

Or without touching the filesystem: **Data → Load your own data** in the app, or
`curl -F file=@panel.csv http://localhost:8000/api/upload`. The upload path runs
the identical code and reports which optional columns it had to drop.

## Sensitivity test (worth running before you defend anything)

```bash
python -m environ.data.generate_data --level-bp 0 --momentum-bp 0 --level-vol-pct 0
uvicorn environ.app:app --reload
```

The verdict text flips to a null. If your reading of the dashboard did not
change, you were reading the story, not the data.
